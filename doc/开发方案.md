## 0. 目标与原则

### 0.1 双目标

| 目标 | 说明 |
| ---- | ---- |
| A. 框架升级 | 单体先稳定升到 **Spring Boot 3.4.3**（**JDK 21**），再谈拆分 |
| B. 微服务练习 | 按笔记节奏：拆分 → 注册发现 → Feign → 网关鉴权 → 配置中心 → Sentinel/Seata |

### 0.2 学习原则（请遵守）

1. **先能跑、再拆分、再增强**：不要一上来同时改 Boot 3 + 拆 6 个服务 + Seata。  
2. **每完成一小步就验收**（见各阶段验收清单），避免「全改完才发现起不来」。  
3. **业务路径优先**：用户端「浏览 → 加购 → 下单 → 支付/催单」、管理端「登录 → 菜品/套餐 → 接单」要始终可测。  
4. **自己实现**：方案告诉你「拆什么、调谁、验什么」；笔记告诉你「组件怎么用」；代码是你的练习。  
5. **可选增强后置**：MQ / ES（笔记 day06～day09）不在本方案主线，有余力再加。

### 0.3 建议 Git 策略

每阶段一个分支，合并前打 tag，方便回滚：

```text
main / master          # 当前 2.7.3 单体基线（先打 tag: v1-boot2-monolith）
feature/boot3-upgrade  # 阶段 1
feature/ms-split       # 阶段 2～3
feature/ms-gateway     # 阶段 4
feature/ms-sentinel-seata  # 阶段 5
```

## 2. 版本选型（务必先读）

### 2.1 阶段 1：单体升级到 Boot 3.4.3

| 组件 | 建议版本 | 说明 |
| ---- | -------- | ---- |
| JDK | **21**（本方案选定） | Boot 3 最低 17；21 为 LTS，与 Boot 3.4 官方支持一致 |
| Spring Boot | **3.4.3** | 你的明确目标 |
| MyBatis Spring Boot | 3.0.x | 换 Boot3 配套 starter |
| PageHelper | 2.1.0+ | 选声明支持 Boot3 的版本 |
| Druid | 1.2.23+ 的 `druid-spring-boot-3-starter` | 注意 artifact 名带 `-3-` |
| MySQL 驱动 | `com.mysql:mysql-connector-j` | 废弃 `mysql-connector-java` |
| Knife4j | OpenAPI3 系（如 `knife4j-openapi3-jakarta-spring-boot-starter`） | 弃用 Swagger2 注解 |
| JJWT | 0.12.x | 旧 `0.9.1` 与新 JAXB/`javax` 不友好 |
| Fastjson | 建议迁 **Fastjson2** 或 Jackson | 1.2.x 风险高；可逐步替换 |

### 2.2 阶段 2+：微服务 BOM（与 Boot 3.4.3 对齐）

官方对应关系：

| 产品 | 与 Boot 3.4.x 官方对齐 |
| ---- | ---------------------- |
| Spring Cloud | **2024.0.x**（Moorgate） |
| Spring Cloud Alibaba | **官方矩阵跳过了 2024**：`2023.x`→Boot3.2；`2025.0.x`→Boot3.5 |

**推荐组合（坚持 Boot 3.4.3 时）**：

```text
Spring Boot              3.4.3
Spring Cloud             2024.0.x（取最新 SR，如 2024.0.1）
Spring Cloud Alibaba     2023.0.3.x（如 2023.0.3.4）  ← 非完美官方对齐，需联调验证
Nacos Server             2.3.x / 2.4.x（与客户端匹配即可）
Sentinel / Seata         跟 SCA BOM，不要手写乱升
```

**备选（想少踩 SCA 兼容坑）**：微服务阶段临时升到 Boot **3.5.x** + Cloud **2025.0.x** + SCA **2025.0.0.0**；单体阶段仍可先完成 3.4.3 升级练习。本方案默认你坚持 **3.4.3**。

父 POM 建议同时 `import`：

1. `spring-boot-starter-parent` 或 `spring-boot-dependencies`  
2. `spring-cloud-dependencies`  
3. `spring-cloud-alibaba-dependencies`

## 5. 阶段 1：Spring Boot 升级到 3.4.3（单体）

> **本阶段不要拆微服务。** 目标：同一个 `sky-server` 在 3.4.3 下跑通核心接口。

### 5.1 改造清单（按优先级）

1. **父 POM**  
   - `spring-boot-starter-parent` → `3.4.3`  
   - `java.version` → `21`  

   - 清理/升级 `dependencyManagement` 中过时版本  

2. **命名空间**  
   - 全项目 `javax.servlet` / `javax.websocket` / `javax.annotation` → `jakarta.*`  
   - 重点文件：`ReportService*`、`WebSocketServer`、拦截器、过滤器  

3. **依赖替换**  
   - Druid → `druid-spring-boot-3-starter`  
   - MySQL 驱动坐标更换  
   - Knife4j → OpenAPI3 + 控制器注解改为 `io.swagger.v3.oas.annotations.*`  
   - JJWT API 迁移（创建/解析 Token 的写法会变）  
   - 检查 `spring.redis` 配置：Boot 3 仍可用 `spring.data.redis.*`（注意前缀是否需调整）  

4. **配置**  
   - 删除/替换 Boot2 专有写法；确认 `allow-circular-references` 是否仍需要（尽量消灭循环依赖）  
   - WebMvc / 拦截器注册方式核对（`WebMvcConfigurer`）  

5. **编译与冒烟**  
   - `mvn clean install -DskipTests`  
   - 启动后：`/admin/employee/login`、`/user/dish/list`、下单相关接口  

### 5.2 常见坑

| 现象 | 排查方向 |
| ---- | -------- |
| 大量 `javax` 找不到 | 未改 jakarta 或依赖仍拉 Boot2 |
| Knife4j 空白 / 404 | 仍用 Swagger2 starter；路径与 security 配置 |
| JWT 解析失败 | JJWT 大版本 API 变更；密钥长度 |
| WebSocket 连不上 | `jakarta.websocket` + 端点扫描 |
| 数据源起不来 | Druid starter 坐标错误 |

- [ ] 工程在 **JDK 21 + Boot 3.4.3** 编译通过  

- [ ] 管理端登录、分类/菜品/套餐 CRUD、用户端菜品列表、购物车、下单主流程可用

## 6. 阶段 2：微服务拆分设计

### 6.1 拆分原则（来自 day03）

- **高内聚、低耦合**：按业务纵向拆；通用能力横向抽（文件、支付）。  
- **数据归属**：谁拥有核心表，谁对外暴露接口；其它服务 **禁止** 直连别人的库。  
- **接口稳定**：Feign 暴露的是「契约」，内部表结构可变。  
- **先纵向业务，后横向基础设施**（网关、配置、保护）。

### 6.2 目标服务一览（对齐 day04「苍穹外卖」作业 + 本项目）

| 服务名 | 端口建议 | 职责 | 主要表 / 资源 |
| ------ | -------- | ---- | ------------- |
| `sky-gateway` | 8080 | 统一入口、路由、JWT 校验 | 无业务库 |
| `sky-user` | 8081 | C 端用户、微信登录、地址簿；**B 端员工登录与员工管理** | `user`、`address_book`、`employee` |
| `sky-product` | 8082 | 分类、菜品、口味、套餐、店铺营业状态、菜品/套餐缓存 | `category`、`dish`、`dish_flavor`、`setmeal`、`setmeal_dish`；Redis `SHOP_STATUS` / `dish_*` / `setmealCache` |
| `sky-trade` | 8083 | 购物车、订单、催单、WebSocket 来单提醒、订单定时任务 | `shopping_cart`、`orders`、`order_detail` |
| `sky-report` | 8084 | 工作台、报表统计与导出 | 无自有写库或只读副本；初期 Feign 拉订单/用户/产品统计接口 |
| `sky-pay` | 8085 | 支付（微信支付封装） | 支付流水表（可新建）；调用订单改支付状态 |
| `sky-file` | 8086 | 文件上传（OSS/本地） | 无或仅元数据 |

公共模块（对齐笔记 `hm-common` / `hm-api` / `hm-pojo`）：

| 模块 | 作用 |
| ---- | ---- |
| `sky-common` | 统一返回、异常、JWT 工具、常量、`BaseContext` |
| `sky-pojo` | 实体 / DTO / VO（可按服务再拆，初期先共享降低难度） |
| `sky-api` | **仅** FeignClient + 跨服务 DTO/VO（像笔记 `hm-api`） |

> **员工放哪？** 笔记示例写「用户服务：用户、地址、登录」。苍穹有双端登录，建议员工与 C 端用户同放 `sky-user`（或改名 `sky-auth`），避免再拆一个过碎的员工服务。

### 6.4 数据库拆分（学习环境可用「一实例多库」）

```text
sky_user      ← user, address_book, employee
sky_product   ← category, dish, dish_flavor, setmeal, setmeal_dish
sky_trade     ← shopping_cart, orders, order_detail
sky_pay       ← （可选）payment 流水表
```

生产环境理想是「一服务一实例」；课堂用多 database 即可（笔记同款做法）。

迁移步骤建议：

1. 从 `sky.sql` 拆出各库建表脚本  
2. 先复制数据，双写/对照验证前可只读切流  
3. 每个服务 `application-dev.yml` 只连自己的库  

### 6.5 核心调用关系（Feign）

```text
客户端
  └─▶ sky-gateway
        ├─ /admin/employee/** 、/user/user/** 、/user/addressBook/**  → sky-user
        ├─ /admin|user /category|dish|setmeal|shop/** 、上传可转 file  → sky-product / sky-file
        ├─ /user/shoppingCart/** 、/admin|user /order/**               → sky-trade
        ├─ /admin/workspace/** 、/admin/report/**                     → sky-report
        └─ /pay/**（若独立路径）                                      → sky-pay

sky-trade ──Feign──▶ sky-user     （查地址、用户）
sky-trade ──Feign──▶ sky-product  （加购时查菜品/套餐；可选）
sky-trade ──Feign──▶ sky-pay      （发起支付）
sky-pay   ──Feign──▶ sky-trade    （支付成功改订单状态）
sky-report──Feign──▶ sky-trade / sky-user / sky-product （统计）
```

下单流程改造要点（对照现有 `OrderServiceImpl`）：

1. Feign 查地址（原 `AddressBookMapper`）  
2. 读本库购物车；空则失败  
3. 写 `orders` + `order_detail`  
4. 清空本库购物车  
5. WebSocket 通知仍放 `sky-trade`  
6. 跨库事务：阶段 3 可先「最终一致 / 本地事务」；阶段 5 再用 Seata

## 7. 阶段 3：按 day03 落地拆分（Nacos + Feign）

> 对照笔记：拆商品/购物车 → RestTemplate → Nacos → OpenFeign → 抽 `hm-api`。  
> 苍穹建议迁移顺序（由易到难）：

### 7.1 推荐迁移顺序

| 次序 | 动作 | 说明 |
| ---- | ---- | ---- |
| 1 | 建父 BOM + 空模块骨架 | 各服务能空启动并注册 Nacos |
| 2 | 抽 `sky-product` | 分类/菜品/套餐/店铺；管理端+用户端 Controller 一并迁 |
| 3 | 抽 `sky-user` | 员工、微信用户、地址 |
| 4 | 抽 `sky-trade` | 购物车、订单；先 Feign 调 product/user |
| 5 | 抽 `sky-file` / `sky-pay` | 上传与支付从 `CommonController` / 支付逻辑迁出 |
| 6 | 抽 `sky-report` | 工作台与报表改为 Feign 聚合 |
| 7 | 下线或归档 `sky-server` | 全部流量走各服务直连端口（网关下阶段再做） |

### 7.2 每个业务服务的固定动作（模板）

对任意服务重复笔记步骤：

1. 创建 module，引入 web / mybatis / nacos-discovery / loadbalancer 等  
2. 拷贝本域 Controller / Service / Mapper / XML  
3. 独立 `application.yml`：`spring.application.name`、端口、自己的数据源  
4. 注册到 Nacos，控制台能看到实例  
5. 把「跨域依赖」改成 Feign（接口放 `sky-api`）  
6. 启动类：`@EnableFeignClients(basePackages = "com.sky.api")`（包名自定）  
7. Swagger/Knife4j 本服务可单独打开，便于联调  

### 7.3 `sky-api` 约定（对齐 day03 §4.3～4.4）

- 只放：`@FeignClient` 接口、跨服务 DTO、必要的 Fallback 接口（Fallback 可阶段 5 再补）  
- 不要放：Mapper、Service 实现、配置类里的数据源  
- Feign 日志级别可用 `DefaultFeignConfig`（笔记同款）  

### 7.4 阶段 3 临时注意

- **用户 ID 暂时写死**：笔记作业允许先写死；网关鉴权在阶段 4 再统一。  
- **购物车加购**：必须 Feign 查菜品/套餐价格与图片，禁止 trade 连 product 库。  
- **套餐与菜品**：同属 product，可保留本地事务，不必 Feign。  
- **Redis 缓存**：product 服务自己维护；缓存 Key 保持与现网一致，减少前端感知。  

### 7.5 阶段 3 验收

- [ ] Nacos 中可见各业务服务实例  
- [ ] 不经过网关，用各服务端口 + Knife4j 跑通主流程  
- [ ] 购物车/下单路径已是 Feign，无跨库 JDBC  
- [ ] `sky-api` 中 Feign 与笔记 `hm-api` 职责一致

## 8. 阶段 4：按 day04 落地网关与配置

### 8.1 Gateway

1. 新建 `sky-gateway`，依赖：`spring-cloud-starter-gateway`、`nacos-discovery`（**不要**引入 `spring-boot-starter-web`）  
2. 路由示例思路（具体谓词自己写）：

| 路径前缀 | `uri` |
| -------- | ----- |
| `/admin/employee/**`、`/user/user/**`、`/user/addressBook/**` | `lb://sky-user` |
| `/admin/category/**`、`/admin/dish/**`、`/admin/setmeal/**`、`/admin/shop/**`、`/user/category/**`、`/user/dish/**`、`/user/setmeal/**`、`/user/shop/**` | `lb://sky-product` |
| `/user/shoppingCart/**`、`/admin/order/**`、`/user/order/**` | `lb://sky-trade` |
| `/admin/workspace/**`、`/admin/report/**` | `lb://sky-report` |
| `/admin/common/upload` | `lb://sky-file` |
| WebSocket `/ws/**` | 转发到 `sky-trade`（注意网关对 WS 的支持与超时） |

3. 前端 / 小程序 **只配置网关地址**（原 8080）。

### 8.2 统一登录校验（day04 §2）

目标架构：

```text
请求 → Gateway GlobalFilter
        ├─ 白名单：登录、doc、部分公开接口
        ├─ 校验 JWT（管理端 token / 用户端 authentication）
        └─ 通过后把 userId（及端类型）写入请求头，例如 user-info
             ↓
       各微服务拦截器从 Header 取 ID → BaseContext
             ↓
       Feign 请求再经 RequestInterceptor 继续传递 Header
```

对照笔记完成：

- [ ] JWT 工具进 `sky-common`  
- [ ] Gateway `GlobalFilter` 鉴权  
- [ ] 微服务 `HandlerInterceptor` 读 Header  
- [ ] OpenFeign `RequestInterceptor` 传递用户（解决 ThreadLocal 跨线程问题）  

双端差异：苍穹有两套 Secret / Token 名，过滤器里要按路径前缀 `/admin/**` vs `/user/**` 分支，不要照搬黑马商城单用户模型。

### 8.3 Nacos 配置中心（day04 §3）

建议 DataId（示例）：

| DataId | 用途 |
| ------ | ---- |
| `shared-jdbc.yaml` | 可选项：若仍有共享中间件地址 |
| `shared-redis.yaml` | Redis |
| `shared-log.yaml` | 日志 |
| `sky-gateway-routes.json` | 动态路由（笔记 §3.3） |
| `{service}.yaml` | 各服务私有配置 |

注意笔记评论区经验：较新 SCA **不要盲目加** `spring-cloud-starter-bootstrap`；优先用 `spring.config.import=nacos:...`（Config Data 方式），否则热更新可能不生效。

## 9. 阶段 5：按 day05 落地保护与分布式事务

### 9.1 Sentinel

练习顺序（跟笔记）：

1. 部署 Sentinel Dashboard  
2. 服务引入 Sentinel，控制台能看到资源  
3. 对热点接口限流（如菜品列表、下单）  
4. OpenFeign 整合 Sentinel：线程隔离 + Fallback 降级  
5. 熔断：产品服务挂掉时，购物车查询的降级行为（返回无价 / 友好错误）

### 9.2 Seata

适合练手的场景：**支付成功改订单** 或 **下单同时扣减（若你增加库存）**。

苍穹现状下单主要写 trade 库，跨服务点较弱；可刻意设计练习：

- 方案 A：`sky-pay` 记支付成功 + `sky-trade` 改订单状态 → `@GlobalTransactional`  
- 方案 B：下单时 `sky-trade` 写订单 + `sky-product` 扣虚拟库存（需加库存字段）  

步骤跟笔记：准备 undo_log、部署 TC、微服务接 Seata、先搞懂 AT 与 XA 差异再选 AT。

## 12. 风险与刻意简化（避免范围爆炸）

| 点 | 建议 |
| -- | ---- |
| 报表跨库统计 | 初期用 Feign 拉聚合接口；不必上 CQRS/数仓 |
| WebSocket | 保留在 trade；网关要单独测 WS；管理端连网关 WS 路径 |
| 微信登录 / 真实支付 | 可继续 Mock；重点练服务边界与调用链 |
| `sky-pojo` 过大 | 先共享；熟练后再按域拆 jar |
| Boot 3.4 vs SCA | 见 §2.2；联调失败时优先查 BOM 版本，而不是业务代码 |
