# 苍穹外卖（CangQiongWaiMai）项目文档

## 1. 项目概述

苍穹外卖是一套面向餐饮外卖业务的全栈 Demo 项目。主干已从单体升级为 **Spring Boot 3.4.3 + 微服务**：

- **管理端（B 端）**：员工登录、分类/菜品/套餐管理、店铺营业状态、订单处理、工作台与数据报表
- **用户端（C 端）**：微信登录、浏览菜品/套餐、购物车、地址簿、下单支付、催单等

项目根 Artifact：`com.sky:sky-take-out:1.0-SNAPSHOT`  
**统一入口**：`sky-gateway` **8080**（前端 / 小程序 / Nginx 只打网关）  
历史单体 `sky-server` 仅作对照，不要再作为线上入口。

本地一键启动见仓库根目录 [README.md](../README.md)。升级路线：[升级/开发方案.md](./升级/开发方案.md)。

## 4. 系统架构说明

### 4.1 运行时架构

```
客户端（管理后台 / 微信小程序）
        │  HTTP / WebSocket —— 只打网关或 Nginx
        ▼
 sky-gateway :8080
        │  JWT 校验，写入 user-info / user-type
        ▼
  lb:// 各微服务
        │  拦截器读 Header → BaseContext
        │  跨服务 OpenFeign（继续传 Header）
        ▼
  MySQL（分库） / Redis / Sentinel / Seata
```

网关路径见根 [README.md](../README.md)。更细的拆分表：[升级/开发方案.md](./升级/开发方案.md) §6。

### 4.2 双端鉴权（网关统一）

| 端 | Token 请求头名 | 密钥配置项 | 路径前缀 | 白名单示例 |
| -- | -------------- | ---------- | -------- | ---------- |
| 管理端 | `token` | `sky.jwt.admin-secret-key` | `/admin/**` | `/admin/employee/login` |
| 用户端 | `authentication` | `sky.jwt.user-secret-key` | `/user/**` | `/user/user/login`、`/user/shop/status` |

说明：

- **不是**标准 `Authorization: Bearer`，而是自定义 Header 名（由 `JwtProperties` 读取）。
- 流程：Gateway `AuthGlobalFilter` 解析 JWT → 写 `user-info` → 各服务拦截器只读 Header → Feign `RequestInterceptor` 继续传递。
- JJWT 0.12 对短密钥做了 SHA-256 派生；升级后旧 Token 失效，需重新登录。

### 4.3 接口文档

联调主路径走网关 `http://localhost:8080`。各服务仍可单独打开 Knife4j：

- 用户：`http://localhost:8081/doc.html`
- 产品：`http://localhost:8082/doc.html`
- 交易：`http://localhost:8083/doc.html`
- 网关本身无完整业务文档

Header：

- 管理端：`token: <登录返回的 jwt>`
- 用户端：`authentication: <登录返回的 jwt>`

## 5. 核心业务功能

### 5.1 管理端

| 模块 | 路径前缀 | 主要能力 |
| ---- | -------- | -------- |
| 员工管理 | `/admin/employee` | 登录/登出、增删改查、启用禁用、分页 |
| 分类管理 | `/admin/category` | 菜品/套餐分类 CRUD、启停 |
| 菜品管理 | `/admin/dish` | 菜品及口味维护、起售停售、缓存清理 |
| 套餐管理 | `/admin/setmeal` | 套餐及菜品组合、起售停售、缓存驱逐 |
| 订单管理 | `/admin/order` | 条件查询、接单/拒单/取消、派送、完成、状态统计 |
| 店铺状态 | `/admin/shop` | 营业/打烊（Redis 存储） |
| 通用上传 | `/admin/common` | 文件上传 |
| 工作台 | `/admin/workspace` | 今日营业数据、订单/菜品/套餐概览 |
| 数据统计 | `/admin/report` | 营业额、用户、订单、销量 Top10、Excel 导出 |

### 5.2 用户端

| 模块 | 路径前缀 | 主要能力 |
| ---- | -------- | -------- |
| 用户 | `/user/user` | 微信登录 |
| 分类 | `/user/category` | 查询启用分类 |
| 菜品 | `/user/dish` | 按分类查询菜品（Redis 缓存） |
| 套餐 | `/user/setmeal` | 套餐列表（Spring Cache）、套餐内菜品 |
| 购物车 | `/user/shoppingCart` | 加购、减购、列表、清空 |
| 地址簿 | `/user/addressBook` | 地址 CRUD、默认地址 |
| 订单 | `/user/order` | 下单、支付、历史订单、取消、再来一单、催单 |
| 店铺 | `/user/shop` | 查询营业状态 |

### 5.3 订单状态流转

订单状态定义（`Orders` 实体）：

| 状态值 | 含义 |
| ------ | ---- |
| 1 | 待付款 |
| 2 | 待接单 |
| 3 | 已接单 |
| 4 | 派送中 |
| 5 | 已完成 |
| 6 | 已取消 |
| 7 | 退款 |

典型流程：

```
用户下单 → 待付款 → 支付成功 → 待接单
                → 商家接单 → 已接单 → 派送中 → 已完成
                → 超时未支付 / 取消 / 拒单 → 已取消
```

支付状态：`0` 未支付 / `1` 已支付 / `2` 退款。

## 6. 数据库设计

微服务分库脚本：[升级/sql/](./升级/sql/README.md)。历史单体库脚本：项目根目录 `sky.sql`（对照用）。

| 库名 | 表 | 归属服务 |
| ---- | -- | -------- |
| `sky_user` | `user`、`address_book`、`employee` | sky-user |
| `sky_product` | `category`、`dish`、`dish_flavor`、`setmeal`、`setmeal_dish` | sky-product |
| `sky_trade` | `shopping_cart`、`orders`、`order_detail`、`undo_log` | sky-trade |
| `sky_pay` | `payment`、`undo_log` | sky-pay |

表含义：

| 表名 | 说明 |
| ---- | ---- |
| `employee` | 商家员工 |
| `category` | 分类（1 菜品分类 / 2 套餐分类） |
| `dish` | 菜品 |
| `dish_flavor` | 菜品口味 |
| `setmeal` | 套餐 |
| `setmeal_dish` | 套餐与菜品关联 |
| `user` | C 端用户（微信 openid） |
| `address_book` | 收货地址 |
| `shopping_cart` | 购物车 |
| `orders` | 订单主表 |
| `order_detail` | 订单明细 |
| `payment` | 支付流水 |
| `undo_log` | Seata AT 回滚日志 |

核心关系简述：

- 分类 1:N 菜品 / 套餐
- 菜品 1:N 口味
- 套餐 N:N 菜品（经 `setmeal_dish`）
- 用户 1:N 地址 / 购物车 / 订单
- 订单 1:N 订单明细

默认管理员账号（脚本初始数据）：

- 用户名：`admin`
- 密码：`123456`（库中多为 MD5；生产环境务必修改）

## 7. 关键技术点

### 7.1 公共字段自动填充（AOP）

- 注解：`@AutoFill(OperationType.INSERT / UPDATE)`
- 切面：`AutoFillAspect`
- 作用：自动填充 `createTime`、`updateTime`、`createUser`、`updateUser`

### 7.2 Redis 缓存

- **店铺营业状态**：Key `SHOP_STATUS`
- **菜品列表缓存**：Key 形如 `dish_{categoryId}`，管理端变更菜品时清理
- **套餐列表缓存**：`@Cacheable` / `@CacheEvict`，缓存名 `setmealCache`

### 7.3 WebSocket 来单提醒

- 端点：`/ws/{sid}`（经网关转到 `sky-trade`）
- 服务端类：`WebSocketServer`
- 用途：用户下单/催单等场景向管理端推送消息

### 7.4 定时任务（`OrderTask`）

| 任务 | Cron | 说明 |
| ---- | ---- | ---- |
| 支付超时处理 | 每分钟 | 超过约 15 分钟未支付的订单自动取消 |
| 派送中订单处理 | 每天 1 点 | 将符合条件的派送中订单置为已完成 |

### 7.5 全局异常与统一返回

- `GlobalExceptionHandler` 捕获业务异常（对 Knife4j 标注 `@Hidden`，避免扫进文档）
- 接口统一返回 `Result<T>`，分页返回 `PageResult`

### 7.6 报表导出

管理端 `/admin/report/export` 使用 POI 导出运营数据 Excel。

## 8. 配置说明

每个服务一份 `application.yaml` + `application-local.yaml`（`spring.profiles.active: local`）。

| 项 | 位置 |
| -- | ---- |
| 数据源 / Redis | 各服务 `application-local.yaml` 的 `sky.datasource` / `sky.redis` |
| Nacos | `NACOS_ADDR`，默认 `192.168.6.128:8848` |
| Seata TC | `SEATA_ADDR`，默认 `192.168.6.128:8091`（仅 pay / trade） |
| Sentinel | `sky.cloud.sentinel.transport.dashboard`，默认 `localhost:8090` |

Compose / 容器内用环境变量覆盖：`NACOS_ADDR`、`SKY_DATASOURCE_HOST`、`SEATA_ADDR` 等。

微信、OSS、支付相关密钥请通过配置文件或环境变量注入，**不要提交真实生产密钥到仓库**。

## 9. 本地运行指南

完整步骤与端口表以仓库根目录 [README.md](../README.md) 为准。摘要：

### 9.1 环境要求

- **JDK 21**、Maven 3.8+
- Docker Compose（推荐）或已有 MySQL / Redis / Nacos / Sentinel / Seata

### 9.2 初始化

```bash
cd deploy
cp .env.example .env
docker compose up -d
```

首次启动会导入 [升级/sql](./升级/sql/README.md)。不要再用单体 `sky.sql` 作为微服务数据源。

### 9.3 启动顺序

1. 基础设施就绪（Nacos 控制台可打开）
2. 业务服务：user → product → file → trade → pay → report
3. 最后：`sky-gateway` 8080
4. 前端只配网关地址

### 9.4 验证

- Nacos 能看到各服务实例
- `POST http://localhost:8080/admin/employee/login`，之后请求头带 `token`
- 无 Token 访问受保护接口返回 401

## 12. 注意事项

1. 本仓库为学习/演示向外卖系统后端，部分第三方能力（微信登录、支付、OSS）需自行配置有效凭证后才能完整联调。
2. `application-local.yaml` 中的数据库密码、微信密钥等仅适用于本地开发，上线前请更换并做好密钥管理。
3. 菜品/套餐变更后需正确清理 Redis / Cache，否则用户端可能读到旧数据。
4. WebSocket 与定时任务依赖服务进程常驻运行。
5. 自定义 `HttpMessageConverter` 时不要 `converters.add(0, jacksonConverter)`，否则 Knife4j `/v3/api-docs` 可能变成 Base64。
6. `swagger-annotations-jakarta` 须与 springdoc 自带的 swagger-core 版本对齐（当前 2.2.30），否则可能出现 `Schema$SchemaResolution` 缺失。
