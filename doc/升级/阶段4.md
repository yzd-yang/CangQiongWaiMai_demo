# 阶段 4：Gateway + 统一鉴权 + Nacos 配置

> 状态：待开始（前置：阶段 3 近完成，见 [阶段3.md](./阶段3.md) §16 收尾项）  
> 对应方案：[开发方案.md](./开发方案.md) §8  
> 前置：[阶段3.md](./阶段3.md) 各业务服务已注册 Nacos，Feign 主流程可直连端口跑通  
> 对照笔记：day04（Gateway、GlobalFilter 鉴权、OpenFeign 传用户、Nacos 配置 / 动态路由）  
> 分支建议：`feature/ms-gateway`

## 目标

前端 / 小程序 **只打网关** `8080`；JWT 在网关统一校验；用户 ID 经 Header 传到微服务与 Feign 链路。

```text
请求 → sky-gateway(8080)
        ├─ 白名单放行（登录、店铺状态、doc 等）
        ├─ GlobalFilter 校验 JWT（/admin/** vs /user/** 两套密钥）
        ├─ 写入请求头（如 user-info / user-type）
        └─ 按路径 lb:// 转发到各服务
             ↓
       微服务拦截器：只读 Header → BaseContext（不再解析 JWT）
             ↓
       Feign RequestInterceptor：继续带上 Header
```

**本阶段不做**：Sentinel、Seata（阶段 5）。

推荐顺序（**做完一步验收一步**）：

```text
补全 sky-gateway 路由 + Nacos 发现
  → 前端只打 8080 冒烟（先可暂留各服务 JWT）
  → Gateway GlobalFilter 统一鉴权 + 写 Header
  → 各服务拦截器改为读 Header
  → Feign 传递用户头
  → （加分）Nacos 配置中心 / 动态路由
  → WebSocket 经网关联调
```

## 1. 补全 `sky-gateway` 基础



### 1.1 依赖核对

`sky-gateway/pom.xml` 应有：


| 依赖                                             | 说明                        |
| ---------------------------------------------- | ------------------------- |
| `spring-cloud-starter-gateway`                 | 网关（基于 WebFlux）            |
| `spring-cloud-starter-alibaba-nacos-discovery` | 服务发现                      |
| `spring-cloud-starter-loadbalancer`            | `lb://` 必需                |
| `sky-common`（后面鉴权再加）                           | JWT 工具、常量、`JwtProperties` |


**禁止**引入 `spring-boot-starter-web`（与 Gateway 冲突）。

可选：鉴权要用到 Jackson 写 JSON 响应时，Gateway 已自带；一般不必再拉 servlet API。

### 1.2 注册到 Nacos

完善 `sky-gateway` 的 `application.yaml`（地址换成你的）：

```yaml
server:
  port: 8080

spring:
  application:
    name: sky-gateway
  cloud:
    nacos:
      discovery:
        server-addr: 192.168.6.128:8848
```

启动类保持 `@SpringBootApplication` 即可；**不要**加 `@EnableFeignClients`。

- [x] 启动网关后，Nacos 控制台出现 `sky-gateway`
- [x] 业务服务也在线（user / product / trade 至少）

## 2. 配置静态路由（先跑通转发）

在网关 yml 里写 `spring.cloud.gateway.routes`（谓词自己写，下列为目标映射）：


| id（自定）        | Path 谓词（示例）                                                                | uri                    |
| ------------- | -------------------------------------------------------------------------- | ---------------------- |
| user-admin    | `/admin/employee/**`                                                       | `lb://sky-user`        |
| user-c        | `/user/user/**`、`/user/addressBook/**`                                     | `lb://sky-user`        |
| product-admin | `/admin/category/**`、`/admin/dish/**`、`/admin/setmeal/**`、`/admin/shop/**` | `lb://sky-product`     |
| product-user  | `/user/category/**`、`user/dish/**`、`/user/setmeal/**`、`/user/shop/**`      | `lb://sky-product`     |
| trade         | `/user/shoppingCart/**`、`/admin/order/**`、`/user/order/**`                 | `lb://sky-trade`       |
| report        | `/admin/workspace/**`、`/admin/report/**`                                   | `lb://sky-report`      |
| file          | `/admin/common/upload`                                                     | `lb://sky-file`        |
| pay           | `/pay/**`（若你独立了路径）                                                         | `lb://sky-pay`         |
| ws            | `/ws/**`                                                                   | `lb://sky-trade`（见 §7） |


写法示意（一条路由）：

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: sky-user-employee
          uri: lb://sky-user
          predicates:
            - Path=/admin/employee/**
        # ……其余按上表继续加
```

注意：

1. `uri` 里的服务名必须等于各服务 `spring.application.name`
2. 一条路由可写多个 Path：`Path=/user/user/**,/user/addressBook/**`
3. **不要**把 `/inner/`** 暴露给公网；内部 Feign 继续服务间直连，不经网关
4. Knife4j：联调阶段可暂不加 doc 路由；需要时再为各服务加 `/xxx/v3/api-docs` 聚合（非本阶段必做）

冒烟（此时各服务仍自己验 JWT，跟阶段 3 一样带 Token）：


| 步骤      | 请求打到                                                                                |
| ------- | ----------------------------------------------------------------------------------- |
| 管理端登录   | `POST http://localhost:8080/admin/employee/login`                                   |
| 分类列表等   | `http://localhost:8080/admin/category/...`（带 `token`）                               |
| C 端登录   | `POST http://localhost:8080/user/user/login`                                        |
| 加购 / 下单 | `http://localhost:8080/user/shoppingCart/...`、`/user/order/...`（带 `authentication`） |


- [x] 经 **8080** 能登录并调到正确服务（看响应 / 各服务日志）
- [x] 错路径会 404，而不是打到错误服务

前端 / Nginx / 小程序 baseURL 改为网关：`http://localhost:8080`（或你的主机）。

## 3. 网关统一登录校验（day04 核心）



### 3.1 目标行为

```text
白名单 → 直接放行（不写 user-info 也行）
非白名单：
  /admin/** → 读 Header「token」→ 用 adminSecretKey 解析 → empId
  /user/**  → 读 Header「authentication」→ 用 userSecretKey 解析 → userId
校验失败 → 401（可返回统一 JSON，字段风格对齐 Result）
校验成功 → 把 ID 写入下游请求头，再放行
```

建议下游头名（与笔记 `user-info` 对齐即可，团队统一就行）：


| Header      | 示例值              | 含义         |
| ----------- | ---------------- | ---------- |
| `user-info` | `12`             | 当前员工或用户 ID |
| `user-type` | `admin` / `user` | 可选，方便微服务区分 |


**不要**把原始 JWT Secret 配到每个业务服务「再验一遍」作为主方案；本阶段目标是 **鉴权上收网关**。

### 3.2 实现要点（自己写，对齐笔记 GlobalFilter）

1. `sky-gateway` 依赖 `sky-common`（使用已有 `JwtUtil`、`JwtProperties`、`JwtClaimsConstant`）
2. 网关 yml 增加与 user 服务一致的 `sky.jwt.*`（密钥、ttl、token 名必须和发 Token 的服务相同）
3. 实现 `GlobalFilter` + `Ordered`（order 取高优先级，如 `-100`）
4. 白名单至少包含：


| 路径                                          | 原因                          |
| ------------------------------------------- | --------------------------- |
| `/admin/employee/login`                     | 管理端登录                       |
| `/user/user/login`                          | C 端登录                       |
| `/user/shop/status`                         | 店铺状态常公开（对照你现网拦截器排除项）        |
| `/doc.html`、`/webjars/**`、`/v3/api-docs/**` | 若经网关看文档                     |
| 你本地还排除过的路径                                  | 对照各服务 `WebMvcConfiguration` |


1. 按路径前缀选密钥与 Token 头名；Claims 里取 `empId` 或 `userId`
2. 用 `ServerHttpRequest.mutate().header(...)` 写入 `user-info`，再 `chain.filter`

苍穹与黑马商城差异：**两套 Secret + 两个 Header 名**，过滤器里必须分支，不要照搬单用户模型。

### 3.3 网关鉴权验收

- [x] 无 Token 访问 `/admin/category/page` → **401**
- [x] 错误 Token → **401**
- [x] 正确管理端 Token → 200，且下游能收到业务响应
- [x] 用用户端 Token 打管理端受保护接口 → 应失败（密钥/Claims 不通）

## 4. 微服务：拦截器改为「只信 Header」

网关验过 JWT 后，业务服务 **不要再 parseJWT**（避免双份逻辑、也避免内部调用还要带 JWT）。

### 4.1 改什么

各服务现有的 `JwtTokenAdminInterceptor` / `JwtTokenUserInterceptor`（或 `sky-user` 包下同名类）改为：

1. 从请求头读 `user-info`（名称与网关写入的一致）
2. `Long id = Long.valueOf(userInfo)` → `BaseContext.setCurrentId(id)`
3. 缺失或非法 → 401
4. `afterCompletion` 里继续 `BaseContext.removeCurrentId()`（若你原来有）

`/inner/**` 仍排除拦截（Feign 内部接口）；内部接口若需要用户 ID，由调用方通过 Feign 传 Header（见 §5），或接口自己带 `userId` 参数——下单主路径优先走 Header + BaseContext。

### 4.2 哪些服务要改

凡注册了 JWT 拦截器的都要改，至少：

- `sky-user`
- `sky-product`
- `sky-trade`
- `sky-file`（若有管理端上传鉴权）
- `sky-report` / `sky-pay`（若有）

登录发 Token 的逻辑 **留在** `sky-user`，不要挪到网关。

### 4.3 直连端口还能测吗？

改完后：

- **经网关**：正常（网关写 Header）
- **直连 8081/8082/…**：若仍用旧方式只带 JWT、不带 `user-info`，会 401

学习阶段可以：

- 联调统一走网关；或
- 拦截器兼容：有 `user-info` 用头；没有则回退解析 JWT（方便过渡，验收通过后建议删掉回退，避免两套长期并存）

- [ ] 经网关登录后，下单 / 加购时 `BaseContext.getCurrentId()` 正确（打日志看）
- [ ] 业务服务 yml **可以不再保留** `sky.jwt` 解析用途（发 Token 的 `sky-user` 仍要留）

## 5. OpenFeign 传递用户头（day04 必做）

问题：`BaseContext` 是 ThreadLocal；Feign 常在别的线程发请求，**不会自动带上**当前用户。

做法（对齐笔记）：

1. 在 `sky-api` 或 `sky-common` 增加 `RequestInterceptor`（Feign）
2. 从 **当前 MVC 请求**（`RequestContextHolder`）取出 `user-info` / `user-type`，写入 Feign 的 `template.header(...)`
3. 调用方 `@EnableFeignClients` 能扫描到该配置（或在 `DefaultFeignConfig` 里声明为 `@Bean`）

注意：

- 异步线程、`@Async`、定时任务里没有 RequestAttributes 时，Interceptor 取不到头——订单定时关单等本来也不依赖登录用户，可忽略
- 网关 → A 服务 → Feign → B 服务：B 若走 `/inner/**` 且排除了拦截器，则 B 侧不一定需要 BaseContext；若 inner 也要用户，就不要排除拦截器，或 inner 自己读 Header

重点验收路径：

```text
用户带 authentication → 网关 → sky-trade 下单
  → Feign 调 sky-user 查地址（/inner/...）
```

此时即使 inner 不鉴权，**trade 本服务**的 `BaseContext` 必须在下单开头就是对的（来自网关 Header）。若还有「trade Feign 调某个仍校验 Header 的接口」，则 Interceptor 必须生效。

- [x] Feign 发出的请求能在 Wireshark / 日志 / 下游断点看到 `user-info`
- [x] 下单用户 ID 与登录用户一致（不会串成 null 或别人的 ID）

## 6. Nacos 配置中心（day04 §3）

阶段 3 只用了 **发现**；本步把共享配置迁到 Nacos。

### 6.1 依赖与导入方式

各需要拉配置的服务增加：

```xml
<dependency>
  <groupId>com.alibaba.cloud</groupId>
  <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>
```

**优先**用 Config Data（Boot 3 / 新 SCA）：

```yaml
spring:
  config:
    import:
      - optional:nacos:shared-redis.yaml?group=DEFAULT_GROUP
      - optional:nacos:sky-trade.yaml?group=DEFAULT_GROUP
  cloud:
    nacos:
      config:
        server-addr: 192.168.6.128:8848
        file-extension: yaml
```

笔记评论区经验：较新 SCA **不要盲目加** `spring-cloud-starter-bootstrap`；加了可能导致热更新不符合预期。本方案默认 **不用 bootstrap**。

### 6.2 建议 DataId


| DataId                           | 用途                                 |
| -------------------------------- | ---------------------------------- |
| `shared-redis.yaml`              | Redis host/port（product / trade 等） |
| `shared-log.yaml`                | 可选，日志级别                            |
| `shared-jwt.yaml`                | 可选，网关 + user 发 Token 共用 jwt 段      |
| `{spring.application.name}.yaml` | 各服务私有（端口、数据源库名等）                   |
| `sky-gateway-routes.json` 或 yaml | 动态路由（§6.3，加分）                      |


迁移策略：先把 **重复的** Redis / 公共地址抽上去；数据源库名仍放服务私有配置。每迁一项就重启验证，避免一次掏空本地 yml。

- [ ] 改 Nacos 里某项（如日志级别）后，能观察到刷新（需 `@RefreshScope` 的 Bean 才热更；数据源等通常要重启，属正常）
- [ ] 本地敏感密码：学习环境可明文；不要把生产密码写进仓库文档



### 6.3 （加分）动态路由

对齐笔记「把 routes 放到 Nacos」：

1. 网关引入 nacos-config
2. 用 `RouteDefinitionWriter` + 监听配置变更，或采用课堂同款监听器方案
3. 在 Nacos 改一条 Path，**不重启网关**即可生效

不会做动态路由也可以过阶段验收；静态 yml 路由足够主流程。

## 7. WebSocket 经网关

来单提醒在 `sky-trade`，路径一般为 `/ws/**`（以你项目 `WebSocketServer` 为准）。

注意：

1. Gateway 对 WS 要调大超时，例如：

```yaml
spring:
  cloud:
    gateway:
      httpclient:
        websocket:
          max-frame-payload-length: 65536
```

1. 管理端前端 WS 地址改为走网关：`ws://localhost:8080/ws/...`（协议随 https 变 wss）
2. 若握手带 Token，需确认过滤器对 **Upgrade** 请求放行或能取到 Token（很多实现把 WS 握手放白名单，改用其它方式鉴权——学习项目可先白名单 `/ws/`**，能连通即可）

## 9. 常见坑


| 现象                  | 排查                                                                  |
| ------------------- | ------------------------------------------------------------------- |
| 网关启动报 web / MVC 冲突  | 是否误加 `spring-boot-starter-web`                                      |
| `lb://` 503         | 服务没注册、name 不一致、LoadBalancer 依赖缺失                                    |
| 登录 200，其它全 404      | 路由 Path 写漏；或服务 context-path 不一致                                     |
| 鉴权 401 但 Token 明明对  | 网关 `sky.jwt` 与 `sky-user` 发 Token 的密钥/头名不一致；或 admin/user 分支反了       |
| 经网关 401，直连服务却 200   | 服务已改读 `user-info`，直连没带该头（预期）；应走网关                                   |
| Feign 后用户 ID 变 null | 缺 `RequestInterceptor`；或 inner 排除后业务自己没传                            |
| 改配置不热更新             | 没用 `spring.config.import`；或加了 bootstrap 导致混乱；Bean 未 `@RefreshScope` |
| WS 连上又断             | 网关超时、防火墙、过滤器拦了 Upgrade                                              |
| 跨域                  | 网关统一配 CORS（`globalcors`），避免每个服务再散落一套且重复加头                           |
