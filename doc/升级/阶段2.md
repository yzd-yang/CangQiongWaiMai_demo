## 1. 定服务边界（照抄定稿即可）

按业务纵向拆；**禁止** A 服务 JDBC 直连 B 服务的库。


| 服务名           | 端口   | 职责                                | 主要表 / 资源                                                                                                 |
| ------------- | ---- | --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `sky-gateway` | 8080 | 统一入口、路由、JWT（**阶段 4 再做**，阶段 2 只占位） | 无业务库                                                                                                     |
| `sky-user`    | 8081 | C 端用户、微信登录、地址簿；B 端员工登录与员工管理       | `user`、`address_book`、`employee`                                                                         |
| `sky-product` | 8082 | 分类、菜品、口味、套餐、店铺营业状态、相关 Redis 缓存    | `category`、`dish`、`dish_flavor`、`setmeal`、`setmeal_dish`；Redis `SHOP_STATUS` / `dish_*` / `setmealCache` |
| `sky-trade`   | 8083 | 购物车、订单、催单、WebSocket 来单提醒、订单定时任务   | `shopping_cart`、`orders`、`order_detail`                                                                  |
| `sky-report`  | 8084 | 工作台、报表统计与导出                       | 无自有写库；Feign 拉 trade/user/product                                                                         |
| `sky-pay`     | 8085 | 微信支付封装                            | 可选新建支付流水表；Feign 改订单支付状态                                                                                  |
| `sky-file`    | 8086 | 文件上传（OSS/本地）                      | 无或仅元数据                                                                                                   |

| 模块           | 作用                                               |

| `sky-api`    | **新建**：仅 `@FeignClient` + 跨服务 DTO（对齐笔记 `hm-api`） |

## 5. 下单流程改造要点（记在笔记，阶段 3 改代码）

对照现有 `OrderServiceImpl`：

1. Feign 查地址（替换 `AddressBookMapper`）
2. 读 **本库** 购物车；空则失败
3. 写本库 `orders` + `order_detail`
4. 清空本库购物车
5. WebSocket 通知仍放 `sky-trade`
6. 跨库事务：阶段 3 先本地事务 / 最终一致；阶段 5 再上 Seata

购物车加购：必须 Feign 查菜品/套餐，**禁止** trade 连 product 库。
