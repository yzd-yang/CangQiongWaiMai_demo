# 阶段 1：Spring Boot 3.4.3 升级记录

> 状态：**已完成**（单体可启动；接口文档可用）  
> 对应方案：[开发方案.md](./开发方案.md) §5

## 目标

将苍穹外卖单体从 Spring Boot 2.7.3 升到 **3.4.3**，JDK 目标 **21**，不拆微服务。

## 已完成事项

| 项 | 结果 |
| -- | ---- |
| 父 POM Boot / `java.version` | `3.4.3` / `21` |
| `javax` → `jakarta` | servlet、websocket 等已改 |
| MySQL 驱动 | `com.mysql:mysql-connector-j` |
| Druid | `druid-spring-boot-3-starter` |
| PageHelper | `2.1.0` |
| JJWT | `0.12.6`，`JwtUtil` 已重写（短密钥 SHA-256） |
| Knife4j | **Knife4j Next** `com.baizhukui:knife4j-openapi3-jakarta-spring-boot-starter:5.6.0` |
| 注解 | Swagger2 → OpenAPI3（`@Tag` / `@Operation` / `@Schema`） |
| Redis 配置 | `spring.data.redis.*` |
| 文档分组 | `springdoc.group-configs`（管理端 / 用户端） |

## 关键踩坑（备查）

1. **旧 Knife4j 4.x + springdoc 2.3** 在 Boot 3.4 上报 `ControllerAdviceBean` NoSuchMethodError → 改用 Knife4j Next 5.6.0（自带 springdoc 2.8.9）。
2. **`extendMessageConverters` 里 `add(0, JacksonConverter)`** 导致 `/v3/api-docs` 变成 Base64 → 改为只替换已有 converter 的 ObjectMapper。
3. **`sky-pojo` 锁死 swagger-annotations 2.2.22** 与 swagger-core 2.2.30 冲突 → 统一到 2.2.30。
4. JWT Header 仍是自定义名：`token`（管理端）、`authentication`（用户端），不是 `Authorization`。

## 验收

- [x] `mvn clean compile` 通过（本机若仅有 JDK 17，可临时 `-Djava.version=17`；正式环境用 21）
- [x] 启动后可打开 `http://localhost:8080/doc.html`
- [x] 管理端登录等主流程可联调（依赖本机 MySQL/Redis 可达）
