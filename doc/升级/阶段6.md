## 目标

1. **一键起中间件**：不再手敲一长串 `docker run`
2. **可容器化业务服务**：`mvn package` 后能打镜像
3. **前端只打网关**：管理端 / 小程序 / Nginx 一律指向 8080（或 Nginx 80 → 8080）
4. **文档能让后来的自己跑起来**：启动顺序写清楚

```text
基础设施（Compose）
  → 业务服务（IDE 或 --profile apps）
      sky-user / product / trade / report / pay / file
  → 网关 sky-gateway:8080
  → （可选）Nginx:80 反代网关
  → 前端 / 小程序只配这一个 API 地址
```

**本阶段不做**：K8s、生产级高可用、把 `sky-server` 单体重新接回流量。

推荐顺序（**做完一块验收一块**）：

```text
docker compose up -d 起中间件
  → 对照端口改 application-local.yaml（若不用 192.168.6.128）
  → IDE 按顺序起业务服务 + 网关
  → 前端 / Knife4j 只打 8080 冒烟
  → （可选）mvn package + --profile apps 验证镜像
```

```bash
cd deploy

docker compose up -d
docker compose ps
```

第一次拉镜像较慢。Nacos 就绪大约 30～60 秒。

## 2. 各服务 Dockerfile

每个可运行模块一份，构建前必须先打出可执行 jar：

```bash
# 在仓库根目录
mvn -pl sky-user,sky-product,sky-trade,sky-report,sky-pay,sky-file,sky-gateway -am package -DskipTests
```


| 模块 | 端口 | 镜像构建 |
| ---- | ---- | -------- |
| `sky-user` | 8081 | `docker build -t sky-user:1.0 ./sky-user` |
| `sky-product` | 8082 | … |
| `sky-trade` | 8083 | … |
| `sky-report` | 8084 | … |
| `sky-pay` | 8085 | … |
| `sky-file` | 8086 | … |
| `sky-gateway` | 8080 | … |

容器内通过环境变量覆盖地址（yaml 里已留占位符）：

- `NACOS_ADDR=nacos:8848`
- `SKY_DATASOURCE_HOST=mysql`
- `SKY_REDIS_HOST=redis`
- `SEATA_ADDR=seata:8091`
- `SKY_CLOUD_SENTINEL_TRANSPORT_DASHBOARD=sentinel:8858`

一键起业务容器（**不要和 IDE 里已占用的 8080～8086 混跑**；也 **不要** 同时加 `--profile nginx`，会和 `nginx-apps` 抢 80 端口）：

```bash
# 先改 deploy/.env：SEATA_IP=seata
cd deploy
docker compose --profile apps up -d --build
```

- [ ] `http://localhost:8080/admin/employee/login` 可登录（经网关）

## 3. 前端 / Nginx 只反代网关

**不要**再把小程序、管理端分别指向 8081、8082……

| 客户端 | 应配置的 API 根地址 |
| ------ | ------------------- |
| 管理端 Vue | `http://<网关>:8080` 或 Nginx `http://<主机>` |
| 微信小程序 | request 合法域名 = 网关或 Nginx |
| Knife4j / Postman | 一律走 8080 |

配置文件：

- 业务也在 Compose 里：`deploy/nginx/nginx.conf`（`--profile apps` 已挂载）
- 网关在 IDE、只要一个 80 入口：`deploy/nginx/nginx.host.conf`

```bash
cd deploy
docker compose --profile nginx up -d nginx
```

WebSocket 来单提醒路径仍是 `/ws/{sid}`，必须经过网关；Nginx 已开 `Upgrade`。

管理端 / 小程序改 baseURL 的具体文件因前端仓库而异，说明见 [前端页面.md](../../frontend/前端页面.md)。

- [ ] 浏览器只访问网关（或 Nginx）即可登录
- [ ] 无 Token 访问受保护接口仍 401（阶段 4 行为不变）

## 4. 启动顺序（验收用）

**推荐学习姿势（Mode A）**：Compose 只起中间件，业务服务用 IDE。

```text
1. docker compose up -d
2. 等 Nacos 控制台可打开
3. 启动业务（无硬依赖顺序，建议）：
     sky-user → sky-product → sky-file
     sky-trade → sky-pay → sky-report
4. 最后启动 sky-gateway（8080）
5. 前端 / Knife4j 只打网关
```

**可选（Mode B）**：`--profile apps` 全容器化。把 `.env` 的 `SEATA_IP` 设为 `seata`。

冒烟：

1. `POST /admin/employee/login`（admin / 123456）
2. `GET /user/dish/list?categoryId=...`（需用户 Token 或走白名单外接口前先登录）
3. 加购 → 下单 → 支付（mock）
4. 管理端 WS：`ws://<网关>/ws/1`

## 5. 常见坑


| 现象 | 排查 |
| ---- | ---- |
| 3306 启动失败 | 本机 / 群晖已有 MySQL；停旧容器或改 compose 端口 |
| Nacos 控制台打不开 | 等 1 分钟；看 `docker compose logs nacos`；确认 8848 |
| 客户端连上 8848 但注册失败 | Nacos 2.x 还要通 **9848**（gRPC），compose 已映射 |
| Seata 连不上 / 回滚异常 | `SEATA_IP` 必须是**客户端能访问的地址**；IDE 跑业务时不要填 `seata` |
| Sentinel 控制台空 | 先访问一次业务接口；dashboard 应对 8090（容器内 8858） |
| 镜像 `COPY jar` 失败 | 没 `mvn package`；或 `spring-boot-maven-plugin` 未生效 |
| 前端部分接口 404 | 仍指向旧单体端口，未改成网关 |
| 初始化 SQL 没导入 | 数据卷是旧的；`down -v` 后重来 |
